## 三、分析模式

### 1. 双版本比较 `DOUBLE_VERSION`

请求示例：

```json
{
  "analysisType": "DOUBLE_VERSION",
  "oldFileGetPath": "/合同目录/修改前.docx",
  "newFileGetPath": "/合同目录/修改后.docx",
  "resultMode": "SIMPLE"
}
```

- `analysisType` 未传或为 `null` 时默认 `DOUBLE_VERSION`，兼容旧请求。
- 必填 `oldFileGetPath`、`newFileGetPath`。
- 从服务器 SFTP 下载 DOCX，使用 Aspose.Words 19.9 比较。
- 不调用大模型、Embedding、向量模型或数据库。
- 返回条款级 `ADDED`、`DELETED`、`MODIFIED`。
- 每条变化包含 `changedParagraphs`，每个段落包含 `INSERTED`、`DELETED`、`REPLACED` 明细。
- 日期、金额、比例、版本号、标点、人员名称变化已做精细化处理。
- `resultMode=SIMPLE`：只返回变化段落，不返回 `context`。
- `resultMode=CONTEXT`：额外返回完整变更前后条款上下文。
- 修改条款的上下文不重复包含子条款；整条新增或删除的上下文包含完整子树。
- 不恢复条款 ID、位置、下标、`oldBlocks/newBlocks`。
- Excel：SIMPLE 9 列，CONTEXT 11 列；文件名 `contract-compare-result.xlsx`。

### 2. 单文件变更提取 `CHANGE_DOCUMENT`

请求示例：

```json
{
  "analysisType": "CHANGE_DOCUMENT",
  "changeFileGetPath": "/合同目录/变更函.docx",
  "resultMode": "SIMPLE"
}
```

- 只校验 `changeFileGetPath`。
- 已彻底移除 `changeDocumentType` 请求字段、枚举和响应字段。
- 补充协议、征询意见函、协商函使用统一的内容规则识别，不从文件名推断类型。
- “上传文档”仍指传入服务器 SFTP 路径，未增加 multipart 上传接口。
- 读取普通段落、Word 自动列表、表格和文本框，并按正文顺序处理。
- 识别数字加顿号/点号且包含 `《基金合同》` 的变更标题，也识别“自本协议/函件的变更执行日起”类标题。
- 支持修改、新增、删除、多项连续变更、同段标记和文档末尾变更。
- 修改类以“内容变更如下”等标记拆分旧内容和新内容。
- 针对真实变更函已修复双引号内容截断：能够跨 Word 段落收集一对中文双引号包围的完整新内容，不会只返回开头的“（三）投资策略”。
- 引号闭合后面的流程说明不会混入变更内容。
- 单文件响应包含 `sourceHeading`、`targetClauseReference`；不返回 `context`，`resultMode` 对该模式不产生展示差异。
- 无法确认的局部内容通过 `warnings` 返回；完全无可读正文或未识别标题时返回业务码 400。
- Excel 固定 8 列；文件名 `contract-change-extract-result.xlsx`。

## 四、公共响应

- 顶层业务字段：`totalChanges`、`changes`、`warnings`。
- 条款变更：`ClauseChange`。
- 段落变更：`ChangedParagraph`。
- 明细类型：`INSERTED`、`DELETED`、`REPLACED`。
- 业务码：200 成功、400 请求或文件业务错误、500 内部处理失败、503 比较引擎暂不可用。
- `warnings` 非空仍可能有可用结果，调用方应展示并标记人工复核。

## 八、2026-09-16 新增：比对后业务类型识别

本节覆盖前文中“合同比对不调用 Embedding”的旧边界：生产 `/compare` 已接入历史向量类型识别，
因此必须携带 `UserId` 请求头。临时 `/export` 保持基础导出职责，不要求 `UserId`，不调用模型或
历史向量索引。

- 新增“变化段落优先、上下文兜底”：新增/修改使用新段落，删除使用旧段落；仅
  `NO_RELIABLE_MATCH` 才尝试上下文，上下文结果最高为 `CANDIDATE`。
- 模型或索引故障按变化段落降级，基础比对/提取结果仍返回，失败数量写入 `warnings`。
- 响应新增预测汇总、段落级 `businessTypePrediction`，以及文件级 `fileChangeTypeCodes`。文件级

- 不保存审核任务，不提供确认回写接口，预测结果不会自动进入 `TPIF_HTDLYB`；历史样本继续
  通过既有 Excel 导入流程维护。
- 不新增数据库表或迁移脚本。
- `/export` 保持原有基础列：双版本 SIMPLE 9 列、CONTEXT 11 列，单文件 8 列；不输出预测字段。
