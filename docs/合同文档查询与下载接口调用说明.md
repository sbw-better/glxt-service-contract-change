# 合同文档查询与下载接口调用说明

## 1. 基本信息

- 请求方式：`POST`
- 请求和响应字符集：UTF-8
- 请求头：`Content-Type: application/json`
- 接口根路径：`/service/contract-query`

请将示例中的 `<host:port>` 替换为实际部署地址。

| 接口 | 路径 | 说明 |
| --- | --- | --- |
| 查询合同文档 | `/service/contract-query/doc/query` | 按管理人和基准日期查询有效合同文档元数据 |
| 下载合同文档 | `/service/contract-query/doc/download` | 校验管理人归属后下载一个或多个文件 |

## 2. 查询合同文档

### 请求

```http
POST http://<host:port>/service/contract-query/doc/query
Content-Type: application/json
```

```json
{
  "managerId": 525,
  "baseDate": "2026-10-09",
  "queryDays": 3
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `managerId` | Long | 是 | 管理人 ID |
| `baseDate` | String | 是 | 查询基准日，格式为 `yyyy-MM-dd` |
| `queryDays` | Integer | 否 | 查询天数，范围 `0–6`；省略时默认为 `0`。显式传 `null` 不合法 |

查询日期范围为闭区间：`baseDate - queryDays` 至 `baseDate`。例如基准日为 `2026-10-09`、查询天数为 `3`，查询范围为 `2026-10-06` 至 `2026-10-09`。

仅返回管理人名下、有效状态为 `1`、文档分类为 `106` 或 `108` 的文档。筛选日期使用生效日期；生效日期为空时使用上传日期。

### 成功响应

HTTP 状态为 `200`，业务响应结构如下；无匹配记录时 `data` 为空数组。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "fileId": 123456,
      "productCode": "基金代码",
      "productName": "基金名称",
      "contractVersion": "1-0",
      "fileName": "合同文件.docx",
      "categoryCode": 106,
      "effectiveDate": "20261001",
      "updatedAt": "2026-10-01 12:30:45"
    }
  ]
}
```

`fileId` 可用于下载接口的 `fileIds`。`effectiveDate` 可为空；更新时间格式为 `yyyy-MM-dd HH:mm:ss`。

## 3. 下载合同文档

### 请求

```http
POST http://<host:port>/service/contract-query/doc/download
Content-Type: application/json
```

```json
{
  "managerId": 525,
  "fileIds": [123456, 123457]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `managerId` | Long | 是 | 管理人 ID，必须为正数 |
| `fileIds` | Long 数组 | 是 | 一个或多个文件编号；数组不能为空，每个编号必须为正数 |

下载前会一次性校验所有文件编号是否存在且属于该管理人，并且文档仍有效、分类为 `106` 或 `108`。任一编号未通过校验时，整批不下载并返回 HTTP `404`。重复的文件编号会去重。

### 成功响应

- 一个唯一文件编号：HTTP `200`，响应体为文件内容，`Content-Type: application/octet-stream`。
- 多个唯一文件编号：HTTP `200`，响应体为 ZIP 压缩包，`Content-Type: application/zip`；压缩包中的文件按请求顺序命名为 `基金合同_时间戳_001.docx`、`基金合同_时间戳_002.docx` 等。
- 下载文件名通过 `Content-Disposition` 提供：单文件为 `基金合同_时间戳.docx`，多个文件为 `基金合同_时间戳.zip`。

响应为文件流，不是 JSON。使用支持 UTF-8 `filename*` 的客户端下载时会显示中文文件名。Postman 的“保存响应”对话框可能采用兼容备用名 `Contract_时间戳.docx` 或 `Contracts_时间戳.zip`。

### cURL 示例

下载单个文件：

```bash
curl -X POST "http://<host:port>/service/contract-query/doc/download" \
  -H "Content-Type: application/json" \
  -d '{"managerId":525,"fileIds":[123456]}' \
  -OJ
```

下载多个文件（服务返回 ZIP）：

```bash
curl -X POST "http://<host:port>/service/contract-query/doc/download" \
  -H "Content-Type: application/json" \
  -d '{"managerId":525,"fileIds":[123456,123457]}' \
  -OJ
```

`-O -J` 让 cURL 根据服务端的 `Content-Disposition` 文件名保存响应。

## 4. 参数错误和其他响应

参数缺失或格式错误时，接口通过统一业务响应体返回错误信息，例如：

```json
{
  "code": 400,
  "message": "查询天数不能大于6",
  "data": null
}
```

下载接口的文件不存在或管理人归属校验失败时返回 HTTP `404`，响应体为空。下载存储服务异常时由服务端统一异常处理。
