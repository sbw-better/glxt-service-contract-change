# 模型升级同步重建说明

适用于几百条历史样本、低频模型升级的当前单实例服务。普通导入和版本升级均在请求线程同步执行；不使用后台执行器、消息队列或异步受理响应。

## 版本与数据范围

`MODEL_VERSION`是包含模型名称、维度和版本的完整兼容标识，只做整体比较。控制表另外保存实际调用模型名称，防止标识未更新但实际模型已变。

- 同版本、同模型名称、同维度：增量导入，新增、同标签重复跳过、同标签停用重启、标签冲突拒绝。
- 同版本但模型名称或维度不同：业务409拒绝导入，预测503不可用，必须更新版本标识。
- 不同且从未使用过的版本：全量重建。目标已有历史行则禁止复用；旧版本记录保留，不自动删除。
- 空库首次导入：同步建立有效模型身份。已有历史但控制信息缺失或未初始化则拒绝写入，不推断模型名称。
- 新库控制行初始化显式写入`ID=1`、`REVISION=0`、`OPERATION_STATUS='IDLE'`，同时保留状态字段的`DEFAULT 'IDLE' NOT NULL`定义。已有控制行不得重复插入；已有历史样本的模型身份仍需明确初始化。

升级只读取`SFSX=1`的源样本，人工停用和历史失效版本不恢复。源正文规范化、Hash、标签、版本及维度必须一致；发现异常整批终止。与Excel按Hash合并，同标签去重并优先Excel原文，标签不同拒绝。单次Excel最多1000行；合并后的有效样本默认最多10000条，失效版本不计入上限。

## 同步处理顺序

1. 请求线程完成Excel格式、行数、正文、编码和文件内冲突校验。
2. 在短事务中锁定控制行，检查模型兼容性及版本复用，原子占用操作ID。并发导入和人工重载返回409及已有操作ID。
3. 读取当前有效历史并与Excel合并，校验合并数量；仅在请求内保留输入及固定目标配置。
4. 分批调用新模型，严格检查结果数量、维度、数值有限性，归一化并编码为CLOB JSON。所有源样本都重新调用模型，旧向量不作为输入。
5. 全部向量生成成功后，用一个事务检查源版本及修订号，插入所有新行、停用所有旧有效行、切换控制版本及修订号，并记录`DB_COMMITTED`。任何一步失败均回滚。
6. 从新有效版本构建索引，要求数量一致且无坏记录；一次性发布完整快照，再回到`IDLE`并释放操作占用。
7. 同步返回成功统计；普通增量导入仍返回原结构。

新行使用序列产生新ID及当前创建时间；旧行仅修改`SFSX`，正文、Hash、标签、向量、ID和创建时间不变。CLOB数字数组、余弦相似度、Top K、平方加权投票、支持数及合同级汇总规则均未改变。每次批量预测固定一份完整快照，历史不同版本不会重复参与投票。

## 单行控制表

`HT_SAMPLE_LIBRARY`固定一行，保存有效模型名称、完整版本、维度、修订号、操作ID、操作状态及预期样本数，承担数据库互斥、模型身份判定和索引恢复。不使用仅对当前JVM有效的Java锁替代数据库占用。

不新增重建任务表，也不保存逐批进度、历史任务状态、错误或重建审计记录。既有合同分析日志仍保留。UserId仅用于本次模型调用，不保存上传文件、API Key或模型响应。

状态依次为`IDLE → RUNNING → DB_COMMITTED → IDLE`。`RUNNING`包含操作ID；`DB_COMMITTED`同时保存预期样本数，用于重启后严格检查新索引；`IDLE`清除操作ID和预期数。提交前失败释放占用回到`IDLE`，不保存`FAILED`状态。模型调用在事务外，数据库事务只负责占用和最终保存，不在网络等待期间锁住控制行。

## 接口与响应

仍使用`POST /service/contract-change/samples/import`，改为JSON对象参数`fileGetPath`及`userId`，不再使用multipart和UserId请求头。文件按`/compare`的主备SFTP机制读取，仅支持xlsx且最大20MB。普通导入响应结构不变。同步重建完成后响应体示例：

```json
{"code":200,"message":"全量重建完成","data":{"success":true,"rebuild":true,"indexReloaded":true,"operationId":"操作UUID","sourceVersion":"old-v1","targetVersion":"new-v2","totalSamples":301,"insertedSamples":301,"disabledSamples":300}}
```

`insertedSamples`为全部新版本行数，不是仅Excel新增数。没有异步`accepted=true`、202响应或任务查询接口。忙或版本复用为409。项目沿用HTTP200加响应体业务码的封装习惯。

`GET /service/contract-change/index/status`的`modelVersion`与`vectorDimension`来自实际快照，另有`activeModelVersion`、`configuredModelVersion`、`operationId`、`operationStatus`、`recognitionAvailable`。操作ID仅在占用期间保留，空闲时为空，不支持按ID查询历史结果。

## 故障和恢复

| 情况 | 数据库状态 | 处理 |
|---|---|---|
| 校验、模型调用失败 | 旧有效版本不变 | 修复原因后重新导入 |
| 最终事务失败 | 新增、停用、版本切换全部回滚 | 释放占用回到IDLE，修复后重试 |
| 已提交但索引失败 | 新有效版本已生效，记录DB_COMMITTED | 识别暂停，调用index/reload或重启；不再生成和插入 |
| 提交前进程退出 | 旧有效版本不变 | 单实例重启释放RUNNING占用，不自动续跑 |
| 提交后进程退出 | 新有效版本为准 | 单实例启动严格加载新索引后回到IDLE |

升级配置生效后、重建成功前，旧库虽保持有效但与新配置不兼容，因此类型识别不可用；这不等同于旧行已停用。精确匹配也不能绕过兼容检查。合同比对保留基础差异并给出识别失败警告。失败重载只允许保留与调用模型兼容的旧快照，不把新模型查询向量与旧索引混用。

同步接口等待时间受模型延迟和重试影响。以300条、每批16条为例，需要19批；不能仅凭样本数量保证固定响应时间。应按实际耗时设置客户端及代理超时。超时后先查状态：RUNNING应等待，DB_COMMITTED应恢复索引；目标有效版本且IDLE、识别可用表示已切换成功。状态只代表当前库，不是历史请求凭证；不能确定结果时先核验有效样本，不盲目重复提交。

## 部署与验证边界

本次只交付代码、初始化结构及说明，不执行已有库迁移、控制信息自动初始化或清库。`01_schema.sql`仅用于新库，复合唯一约束和控制信息的存量初始化须另行确认。只支持单实例、修改配置并重启，不提供多实例索引广播或热切换。

模型测试使用固定向量替身，不等同于真实Embedding网关联调。隔离Oracle测试使用随机新建对象并在结束时清理，不修改现有业务表。真实Oracle环境为23，未验证11g；测试结果详见[本次测试记录](../test-reports/模型升级同步重建验证记录20261009.md)。
