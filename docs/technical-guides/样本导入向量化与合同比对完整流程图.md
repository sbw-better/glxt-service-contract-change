# 样本导入向量化与合同比对完整流程图

本图依据2026年10月12日项目代码整理。当前历史样本导入接收JSON服务器路径，不通过HTTP上传文件；`/compare`先提取文本变化，再利用有效历史样本识别业务变更类型。以下模型维度、容量和阈值均为默认配置，实际以部署配置为准。

## 1 总体数据流

```mermaid
flowchart TB
    A["人工准备Excel：合同段落＋变更类型编码"] --> B["LiveBOS上传附件到文件服务器"]
    B --> C["POST /samples/import<br/>JSON：fileGetPath、userId"]
    C --> D["主备SFTP读取Excel<br/>解析、规范化、Hash、标签校验"]
    D --> E["同版本增量导入<br/>或新版本全量同步重建"]
    E --> F["Embedding网关生成向量<br/>校验＋L2归一化"]
    F --> G[("TPIF_HTDLYB<br/>正文、标签、CLOB JSON向量")]
    E --> H[("HT_SAMPLE_LIBRARY<br/>模型身份、修订号、操作状态")]
    G --> I["构建并整体发布JVM内存索引<br/>Hash映射＋历史向量列表"]
    H --> I
    J["LiveBOS提交合同服务器路径<br/>POST /compare"] --> K["双版本比较／单份变更函提取"]
    K --> L["变化段落类型识别<br/>精确匹配／向量检索／加权投票"]
    I --> L
    L --> M["上下文兜底＋文件级类型汇总"]
    M --> N[("分析主记录＋段落明细＋匹配证据")]
    N --> O["返回analysisId、analysisStatus<br/>fileChangeTypeCodes"]
```

历史样本标签来自Excel人工提供的编码。模型负责将文本转换为向量，业务类型由历史标签和检索规则产生。`/compare`不会自动把变化段落写入历史样本库。

## 2 Excel读取校验与导入分流

```mermaid
flowchart TB
    A["接收SampleImportRequest<br/>fileGetPath＋userId"] --> B{"两个字段非空？"}
    B -- 否 --> E["业务400：参数错误"]
    B -- 是 --> C["校验xlsx扩展名<br/>主SFTP下载；失败尝试备用SFTP<br/>下载过程中限制20MB"]
    C -- 下载失败／超限 --> E
    C --> D["解析第一张Sheet的前两列<br/>表头必须为合同段落、变更类型编码"]
    D --> F["跳过完全空行<br/>统计非空行，默认最多1000行"]
    F --> G["段落规范化：全角空格、换行、连续空白<br/>保留否定词、数字、主体、标点<br/>非空且默认不超过2000字符"]
    G --> H["标签校验、去重、排序<br/>英文分号保存；单码≤64字符，总长≤4000<br/>计算规范化段落SHA-256"]
    H --> I["Excel内部按Hash去重<br/>同Hash同标签跳过重复行<br/>同Hash不同标签记录错误"]
    I --> J{"表头／行数／正文／标签有错误？"}
    J -- 是 --> K["整批拒绝，返回errors行号及原因<br/>不调用模型、不写样本库、不占用控制行"]
    J -- 否 --> L["生成operationId<br/>短事务锁定ID=1控制行"]
    L --> Q{"控制行和目标模型允许操作？"}
    Q -- 否 --> R["409：控制未初始化、已有操作、<br/>同版本配置不一致或目标版本已使用"]
    Q -- 是 --> S["要求占用UPDATE恰好影响1行<br/>IDLE→RUNNING，保存operationId"]
    S --> T{"控制库版本为空<br/>或与配置版本相同？"}
    T -- 是 --> U["执行普通增量导入：图3"]
    T -- 否 --> V["执行新模型同步重建：图4"]
```

控制缺失时拒绝操作；模型身份未初始化但已有历史记录时也拒绝，不自动推断实际模型名称。目标`MODEL_VERSION`作为完整字符串比较；同版本还必须核对实际模型名称和维度。空库首次导入建立模型身份。初始化控制行显式设置`ID=1、REVISION=0、OPERATION_STATUS=IDLE`。

Java侧还核对控制行的状态、操作ID、预期样本数和模型身份是否一致；非法组合不会自动重置，也不会启用识别。

## 3 同版本增量导入及向量化

```mermaid
flowchart TB
    A["已通过Excel校验并持有RUNNING占用"] --> B["按目标MODEL_VERSION＋TEXT_HASH<br/>批量查询已有样本"]
    B --> C{"逐条分类"}
    C -- 没有记录 --> D["加入新增列表"]
    C -- 同标签且当前生效／模型维度一致 --> E["skipped＋1，不调用模型"]
    C -- 同标签但停用 --> F["加入重新启用列表<br/>保留原记录ID，重新生成向量"]
    C -- 标签不同 --> G["整批拒绝：success=false<br/>返回冲突行号，不写入任何样本"]
    D --> H["核对有效样本容量<br/>当前有效数＋新增数＋重启数≤10000"]
    F --> H
    E --> H
    H -- 超限 --> G
    H --> I["合并新增与重启列表<br/>在数据库事务外完成全部向量生成<br/>每批默认16，最多16"]
    I --> J["网关请求：model、input、dimensions、encoding_format<br/>服务端API Key＋透传UserId"]
    J --> K["检查数量、index顺序、维度、有限值及Float32范围<br/>向量L2归一化；保存前编码成JSON数字数组"]
    K -- 失败 --> L["无样本写入<br/>释放本操作RUNNING→IDLE，返回异常"]
    K --> M["单个短事务：核对源版本、revision、operationId<br/>新增／更新样本，设置模型身份，revision＋1"]
    M -- 失败 --> L
    M --> N["提交后读取Oracle有效样本<br/>构建临时索引并整体替换旧快照"]
    N -- 成功 --> O["success=true，indexReloaded=true"]
    N -- 失败 --> P["数据保留：success=true<br/>indexReloaded=false，提示人工重载"]
    O --> Q["finally释放本操作RUNNING→IDLE"]
    P --> Q
    G --> Q
```

返回统计为`totalRows、inserted、updated、skipped、indexReloaded、errors`。全是同标签有效重复样本时不调用模型，仍执行模型身份／修订号处理及索引刷新。普通导入索引刷新失败后，仅版本兼容的已有可用快照可以继续识别。

同版本查重还检查返回记录的维度、生效状态、规范标签及Hash唯一性。异常记录整批拒绝，不当作停用记录自动重新向量化。增量事务写入前必须确认对应操作仍处于RUNNING。

## 4 新模型版本同步重建与失败恢复

```mermaid
flowchart TB
    A["配置版本不同且从未使用过<br/>持有RUNNING操作占用"] --> B["读取全部当前有效历史样本SFSX=1<br/>不恢复旧版本失效／人工停用记录"]
    B --> C["严格校验历史正文、规范化、Hash、标签、版本和维度"]
    C --> D["合并有效历史＋本次Excel<br/>同Hash同标签：Excel原文优先<br/>同Hash不同标签：拒绝整批"]
    D --> E{"历史数据合规且合并容量≤10000？"}
    E -- 否 --> F["拒绝重建，释放RUNNING<br/>旧有效版本不变"]
    E -- 是 --> G["固定目标模型配置<br/>事务外分批生成合并后全部新向量<br/>每批前及提交前检查配置未变"]
    G -- 模型／向量失败 --> H["503：旧有效版本未改变<br/>释放RUNNING，修正后可重试"]
    G --> I["一个原子事务：<br/>锁控制行，核对源版本／revision／操作ID<br/>确认目标未使用、源有效数量未变化"]
    I --> J["插入全部新版本样本：新ID、新创建时间<br/>旧有效行SFSX=0，保留旧正文／标签／向量／ID<br/>切换模型身份，revision＋1<br/>RUNNING→DB_COMMITTED，记录预期样本数"]
    J -- 任一步失败 --> H
    J -- 提交成功 --> K["严格构建新版本索引<br/>坏记录数=0<br/>有效向量数=预期数，Hash数=预期数"]
    K -- 成功 --> L["整体发布新快照<br/>完成本操作DB_COMMITTED→IDLE<br/>清空operationId及expectedSamples"]
    L --> M["业务200：success=true、rebuild=true<br/>返回版本、操作ID及全量入库统计"]
    K -- 失败 --> N["503：数据已切换，索引待恢复<br/>保留DB_COMMITTED，禁止识别<br/>不能按普通失败重复导入"]
    N --> O["人工/index/reload或重启<br/>只从数据库严格恢复索引<br/>不再次调用模型，不再次插入"]
    O -- 成功 --> L
    O -- 失败 --> N
```

升级返回`operationId、sourceVersion、targetVersion、totalSamples、insertedSamples、disabledSamples`。这里的入库统计是合并后的全量数量。`release`只能释放本操作的`RUNNING`，不会清掉`DB_COMMITTED`。

DB_COMMITTED索引恢复始终使用控制表保存的EXPECTED_SAMPLES，调用方不能用空参数绕过严格数量校验。

## 5 compare主流程和文件差异提取

```mermaid
flowchart TB
    A["POST /service/contract-compare/compare<br/>JSON：instId、userId、analysisType及活动文件路径"] --> B["校验instId正数、userId非空且trim后≤100<br/>analysisType必填，活动路径非空且≤1000"]
    B -- 失败 --> C["返回业务校验错误<br/>尚未创建分析记录"]
    B --> D["生成analysisId<br/>独立短事务插入HT_ANALYSIS_LOG<br/>状态PROCESSING"]
    D --> E{"analysisType"}
    E -- DOUBLE_VERSION --> F["主备SFTP下载oldFileGetPath＋newFileGetPath"]
    F --> G["Aspose加载、文档比较、取得Revision<br/>解析旧新合同条款结构"]
    G --> H["条款匹配：精确正文→唯一标题→模糊匹配<br/>Revision定位并记录无法可靠定位的警告"]
    H --> I["合并ADDED／MODIFIED／DELETED条款<br/>切分变化段落，生成具体文字差异及上下文<br/>排序并避免未匹配父子条款重复输出"]
    E -- CHANGE_DOCUMENT --> J["主备SFTP下载changeFileGetPath"]
    J --> K["Aspose读取段落、列表编号及表格文本块<br/>确定性规则定位变更标题和内容段<br/>提取新增／修改／删除及原文、新文"]
    I --> L["形成完整ContractCompareResponse<br/>changes＋changedParagraphs＋warnings"]
    K --> L
    L --> M["变化段落类型识别及上下文兜底：图6、图7"]
    M --> N["文件级汇总与分析留痕：图8"]
    F -. 下载／解析异常 .-> O["独立事务标记FAILED并记录错误<br/>重新抛出异常，由统一响应处理"]
    G -. 异常 .-> O
    K -. 无可解析文本／无变更标题等 .-> O
    N -. 最终持久化等异常 .-> O
```

基础差异的条款模糊匹配是文本规则，不是历史样本向量检索。Aspose Revision用于定位和辅助核查，结构化文本差异也会保留；无法细分的变化可能按整段替换并给出警告。

## 6 compare变化段落识别与上下文兜底

```mermaid
flowchart TB
    A["遍历所有changedParagraphs"] --> B{"段落是DELETED？"}
    B -- 是 --> C["取oldContent<br/>OLD_PARAGRAPH"]
    B -- 否 --> D["取newContent<br/>NEW_PARAGRAPH"]
    C --> E["按导入相同规则规范化"]
    D --> E
    E --> F{"正文为空／超过2000字符？"}
    F -- 为空 --> G["FAILED：无可识别内容"]
    F -- 超长 --> H["SKIPPED_TOO_LONG<br/>不截断正文，不调用模型"]
    F -- 合法 --> I["按规范化正文分组去重<br/>每个不同文本只预测一次，回填各原段落"]
    I --> J["宽容批量预测：图7<br/>失败批次仅标记该批，保留其他结果"]
    J --> K{"当前段落NO_RELIABLE_MATCH？"}
    K -- 否 --> P["保留MATCHED或FAILED等结果"]
    K -- 是 --> L["构造目标段落上下文<br/>标题＋当前完整目标段落＋预算内前后正文<br/>总长度≤2000"]
    L --> M{"上下文非空且不同于原段落？"}
    M -- 否 --> P
    M -- 是 --> N["上下文再次分组预测<br/>双版本：OLD_CONTEXT／NEW_CONTEXT<br/>变更函：标题＋目标段落，不附加全文"]
    N --> O["回填兜底结果，fallbackUsed=true<br/>兜底产生的类型一律降为CANDIDATE"]
    O --> P
    G --> P
    H --> P
    P --> Q["统计matched／noMatch／failed／skippedTooLong<br/>失败或超长添加人工复核warnings"]
    Q --> R["汇总文件类型：图8"]
```

只有没有可靠匹配的段落才尝试上下文兜底，索引／模型失败和超长段落不会进入该兜底。正文轮和上下文轮各自固定一次批量预测快照，整个`/compare`并不是共用一个贯穿所有轮次的快照。

## 7 精确匹配和语义加权投票算法

```mermaid
flowchart TB
    A["开始一次批量预测"] --> B["核对配置、控制库、快照的完整模型版本／名称／维度<br/>检查索引可用，DB_COMMITTED禁止识别<br/>绑定本次批量预测的不可变快照"]
    B -- 不兼容／不可用 --> C["compare宽容模式：INDEX_UNAVAILABLE<br/>相应段落FAILED，保留基础差异"]
    B --> D["规范化＋SHA-256查Hash映射"]
    D --> E{"精确命中？"}
    E -- 是 --> F["EXACT：直接使用历史标签<br/>score=1、supportCount=1、HIGH<br/>不调用Embedding"]
    E -- 否 --> G{"快照为正常EMPTY？"}
    G -- 是 --> H["NO_RELIABLE_MATCH，空证据<br/>不调用Embedding"]
    G -- 否 --> I["其余文本分批调用Embedding<br/>默认16且最多16，L2归一化"]
    I -- 某批业务异常 --> J["该批FAILED<br/>其他批次及精确命中继续保留"]
    I --> K["逐条点积计算余弦相似度<br/>小顶堆召回Top10，按相似度降序"]
    K --> L{"存在similarity≥0.60样本？"}
    L -- 否 --> M["NO_RELIABLE_MATCH<br/>保留实际最高相似度及最多5条真实证据"]
    L -- 是 --> N["取可靠样本前10条投票<br/>样本权重=similarity平方<br/>类型得分=支持该类型权重之和／总样本权重"]
    N --> O{"有类型score≥0.55？"}
    O -- 是 --> P["score≥0.80且supportCount≥2：HIGH<br/>其余达到0.55的类型：CANDIDATE"]
    O -- 否 --> Q{"第一名similarity≥0.80？"}
    Q -- 是 --> R["返回第一名样本全部标签为CANDIDATE<br/>score仍是投票分数，不等于similarity"]
    Q -- 否 --> M
    P --> S["SEMANTIC，类型按score降序／编码排序<br/>附最高相似度、模型版本、最多5条可靠证据"]
    R --> S
    F --> T["按原输入顺序回填结果并释放本批快照绑定"]
    H --> T
    J --> T
    M --> T
    S --> T
```

多个标签的样本会给每个标签贡献完整样本权重，因此多标签得分之和不要求等于1。`similarity`是段落相似度，`score`是历史标签支持比例，两者均不是业务准确率。普通网关4xx直接失败；5xx或网络错误按配置重试，响应格式校验失败不重试。

## 8 文件级汇总、数据库留痕与返回

```mermaid
flowchart TB
    A["取得全部变化段落的最终识别结果"] --> B["按原始变化段落的规范化正文去重<br/>同正文同类型最多算一次证据<br/>同一类型同时HIGH和CANDIDATE时HIGH优先"]
    B --> C{"逐个类型判断"}
    C -- 至少一段HIGH --> D["纳入文件级编码"]
    C -- 至少两个不同段落CANDIDATE --> D
    C -- 只有一段CANDIDATE／无匹配 --> E["不纳入文件级编码"]
    D --> F["编码去重排序<br/>fileChangeTypeCodes"]
    E --> F
    F --> G{"failedCount或skippedTooLongCount大于0？"}
    G -- 是 --> H["analysisStatus=PARTIAL_SUCCESS<br/>保留已完成基础差异和识别结果"]
    G -- 否 --> I["analysisStatus=SUCCESS<br/>无可靠类型或无变化本身不代表失败"]
    H --> J["序列化完整结果JSON"]
    I --> J
    J --> K["一个短事务原子保存<br/>HT_ANALYSIS_PARA_LOG：每个变化段落及预测<br/>HT_ANALYSIS_MATCH_LOG：历史匹配证据与排名<br/>更新HT_ANALYSIS_LOG：状态、编码、耗时、完整JSON"]
    K -- 失败 --> L["回滚本次最终明细事务<br/>独立事务将分析主记录标记FAILED<br/>向调用方返回异常"]
    K -- 成功 --> M["返回业务成功响应<br/>data：analysisId、fileChangeTypeCodes、analysisStatus"]
    M --> N["LiveBOS解析响应并更新调用记录<br/>完整明细保存在服务分析日志表"]
```

`NO_RELIABLE_MATCH`不会单独使合同变为`PARTIAL_SUCCESS`。响应外层成功码和`analysisStatus`应分别判断；项目直接响应通常为`code=200`，宿主环境转换后的外壳以实际集成约定为准。

## 9 控制表状态与启动恢复

```mermaid
stateDiagram-v2
    [*] --> IDLE: 新库显式初始化
    IDLE --> RUNNING: 导入或普通索引重载占用
    RUNNING --> IDLE: 增量完成／失败释放／启动释放残留占用
    RUNNING --> DB_COMMITTED: 升级原子事务提交
    DB_COMMITTED --> DB_COMMITTED: 严格索引恢复失败，识别禁用
    DB_COMMITTED --> IDLE: 严格加载成功并完成对应操作
```

单实例启动先释放残留`RUNNING`，不自动续跑导入；遇到`DB_COMMITTED`时只恢复索引。首次加载尚未完成时为`NOT_READY`，冷启动加载失败时实际标记为`LOAD_FAILED`；通过`/index/status`查看实际快照、配置版本和控制状态。普通构建发现坏向量、正文／Hash不一致、非规范标签或重复Hash会呈现`DEGRADED`，升级恢复则严格拒绝任何坏记录或数量不一致。

索引同时比较当前版本有效数量与按维度读取的数量；被维度过滤掉的有效记录计为坏记录，不能伪装为正常空库。SFTP连接方法保持原实现，沿用既有主备读取机制。

## 10 默认限制和主要数据表

| 项目 | 默认或固定规则 |
|---|---|
| 导入文件 | SFTP服务器xlsx，最大20MB |
| Excel格式 | 第一Sheet前两列：合同段落、变更类型编码 |
| 单次导入 | 默认最多1000条非空数据行 |
| 当前有效样本 | 默认最多10000条，失效旧记录不占容量 |
| 识别段落 | 规范化后默认最多2000字符 |
| 向量维度 | 默认1024，实际须与模型配置一致 |
| 模型批次 | 默认16，代码上限16 |
| 唯一约束 | MODEL_VERSION＋TEXT_HASH |
| 召回／投票／证据 | 默认10／10／5 |
| 相似度门槛 | 默认0.60 |
| 候选／HIGH | 默认score≥0.55；score≥0.80且支持数≥2为HIGH |
| 强相似兜底 | 默认第一名similarity≥0.80，一律CANDIDATE |

| 表 | 作用 |
