## 已确认并修复的问题

| 问题 | 修复前表现 | 修复 |
|---|---|---|
| 损坏Excel的异常分类遗漏 | 后缀xlsx但内容不是Office文件时，POI的NotOfficeXmlFileException可能穿透为系统500 | 保留业务异常，解析阶段IOException及RuntimeException统一转换为明确的Excel业务400；不进入模型或样本写入 |
| 样本INSERT未核对行数 | Mapper返回0行时仍报告保存成功 | INSERT与UPDATE均要求恰好影响1行，否则抛错，由事务回滚 |
| 索引未核对正文与Hash | 向量合法、数量正确但Hash错误时仍能发布，精确匹配可关联错误标签 | 加载时核对原文规范化、保存的规范正文、Hash、规范标签、模型版本、维度、生效状态 |
| 重复Hash导致两套索引不一致 | 语义列表包含重复样本，Hash映射却覆盖为一条，状态仍READY | 重复Hash计为坏记录，不重复加入列表；普通重载DEGRADED，升级严格恢复拒绝发布 |
| 启动错误状态未实际设置 | 控制读取／占用失败时日志声称LOAD_FAILED，状态仍NOT_READY | 冷启动加载失败时实际发布LOAD_FAILED不可用快照 |
| compare写入未使用路径 | 双版本模式把未经校验的changeFileGetPath也写入主记录；超长值可能导致ORA-12899 | 只保存当前分析类型的活动路径，单文件模式同理 |

正文、Hash等坏记录在普通重载中被计为errorCount并跳过；仍有可用样本时保持DEGRADED的原有服务规则。升级DB_COMMITTED恢复继续要求零坏记录、向量数量和Hash数量均与expectedSamples一致。
